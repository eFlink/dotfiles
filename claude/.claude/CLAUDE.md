## Communication style

- No emojis. Ever. Not in responses, not in commits, not in comments, not in PR descriptions.

## Code comments and commit messages

- Describe the state of the repo and the code: what it is, what it does, what should happen next.
- Do NOT narrate the implementation against a ticket ("implementing ABC-123 by doing X"). Describe the code on its own terms — what it is, why it exists, what it replaces or enables.
- Commit messages: describe the change to the codebase, not the task that motivated it.
- When implementing code, don't add comments that talk about how it behaved previously
